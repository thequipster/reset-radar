# 02｜reset-radar 前端重设计方案

> 阶段 2 UX 已获用户认可，现进入阶段 3。阶段 4 扩展授权保留；本文记录 IA、线框、全状态与业务口径。
> 最新裁决撤销此前的风格与配色限制：AI 可自由选择配色、风格、字体与材质，前端按用户选中的图稿还原视觉表达。
> 本文由 RR26 正式落档于 `docs/design/02-spec.md`。等待参考图到位后进入阶段 4 实施；本文尺寸仅作实现参考基准，不限制生图 AI 的像素尺寸。

## 1. 产品目标与设计决定

做一个常驻桌面的安静工具：悬浮时看周额度与风险，展开后知道今天建议追加多少、为什么，以及哪天用卡更合适。

视觉风格与配色由阶段 3 参考图确定；当前不预设默认主题、字体或材质。功能信息层级和业务语义按本方案执行。

信息顺序为：有效公告/采集异常 → 当前额度 → 今日追加建议 → 风险解释 → 用卡规划 → 数据来源与校准。布局不随数值大小换位；强制重置公告有独立区域，避免把公告文本压成风险数字。

三态共享同一份 VM：**悬浮条、短暂迷你预览、点击锁定的展开面板**。不做分别采集数据的三个独立窗口。

## 2. 功能清单：做 / 不做 / 为什么

这里的“不做”表示本次新增范围不纳入，现有功能、字段和解释能力继续保留。

| 范围 | 决定 | 原因 / 依赖 |
|---|---|---|
| 周余额为主的紧凑悬浮条 | 做 | 高频查看；主数值明确写“周余”，风险和卡数保持次级 |
| hover/focus 迷你预览 | 做 | 不点击即可读今日建议；同时支持键盘、点击展开，信息不只靠 hover |
| 展开首屏“今日建议追加” | 做 | 直接回答今日行动；单位为周额度百分点 |
| 周余额 / 短窗余额分别展示 | 做 | 两个窗口不可混用；短窗重置时间暂不新增展示 |
| 风险总分及全部 factors | 做 | 每条 label、带正负号的 delta、note 都可触达；不固定“四条”数量 |
| 今日配速四项解释 | 做 | 均匀配速、风险前拉、软上限、最终建议并列；上限是约束，不画成加项 |
| 今日 / 最佳日用卡期望收益 | 做 | 把 decision 翻译成中文，并展示模型依据、最佳日期和自然重置 |
| cardPlan.outlook 日期收益图 | 做 | 已有候选日输出；以柱长比较期望收益，不创造未来额度轨迹 |
| 强制重置公告 / watch 来源展示 | 做，依赖 RR22/RR23/RR16 | 公告与启发式模型分开；到达计划时刻也不能宣称已确认发生 |
| 加载、空数据、失败、stale、部分缺字段 | 做 | 空值不变成零；保留旧值但标明观测时刻与失效状态 |
| 深浅主题、选中图稿对应的视觉呈现、SVG 图标、焦点反馈、减少动效 | 做 | 深浅外观均由图稿探索，同时满足可访问性 |
| 手动刷新额度 | 做 | 通过已有 refresh_snapshots 采集额度；按钮“刷新额度”，in-flight防连点；公告刷新仍按RR23的数据源契约，不承诺一次操作刷新全部来源 |
| 复制简短状态摘要 | 做 | 输出单位、模型标签、时刻与 stale 标记，便于记录 |
| 本地主题偏好 | 做 | 支持深色、浅色、跟随系统及本地记忆；具体色板与默认外观待图稿选定 |
| 校准摘要 / 数据积累中 | 做，依赖 RR15/RR18/RR17 与只读桥接 | 兑现架构的校准可见性；必须从真实报告/计分结果读入，不按 UI 自行复算 |
| 系统通知、通知阈值、安静时段 | 本次不做新增 | 独立权限与策略需求；ROADMAP 保留，当前通过工具内公告提示 |
| 屏幕边缘自动吸附、位置记忆、多屏恢复 | 本次不做新增 | 单独桌面能力；本次只确保扩展窗口不超出工作区 |
| 隐私模糊模式、数字滚轮动画 | 本次不做新增 | 首先保证语义与可读性；保留轻微刷新反馈 |
| what-if 滑杆、用卡配速联动开关 | 本次不做新增 | 会产生第二套建议上下文；已有纯核心入口保留，另卡明确契约再接线 |
| 实际日消耗轨迹 | 本次不做新增 | adapter 无真实日消耗样本；不能用均匀先验画“真实使用史” |
| 卡到期倒计时 | 本次不做新增 | 上游未给到期时刻；详情明确“未提供”，不凭空补日期 |
| 周 Brier 趋势 / 置信区间 / 未来概率曲线 | 本次不做新增 | 当前计分样本为零且 VM 无相关序列；仅呈现可核验摘要 |
| 多 provider、新数据导出 API、自动用卡 | 本次不做新增 | 当前任务聚焦 Codex；规划只给建议，不执行账户用卡 |

对应阶段 1：采纳 01–09、11–19、21–23、25–27、35、41 的适用部分；10 使用 VM 原始卡数覆盖误导文案；22–24 保留为历史视觉候选，不限定当前图稿；29–34、36–40、42 按上表分拆或暂缓。新增公告区来自当前 BACKLOG RR22/RR23，不把它伪装成已有字段。

## 3. 信息架构与布局

### 3.1 尺寸基准

以下尺寸是实现时的参考基准，单位为 CSS px / Tauri 逻辑尺寸，不是物理截图像素；不约束生图 AI 输出的图稿像素尺寸。

| 形态 | 窗口目标尺寸 | 内容 |
|---|---|---|
| 悬浮条 | 460 × 76 | 四周 8px 透明余量，面板约 444 × 60 |
| 迷你预览 | 460 × 212 | 保留同一悬浮条，在其下增加两行建议、数据状态与展开入口 |
| 展开面板 | 宽 460，高按内容，目标约 690 | 收起/关闭固定可达；内容纵向滚动，最大高度不越工作区 |

保留 RR21 的窗口基础与 PMv2 成果，再调整内容布局。内部断点：内容宽 <400 时把指标双列改为单列，长 label/note 可换行；任何状态都没有横向滚动条。最小可支持宽度目标 360，由实测决定是否开放用户缩放到该值，未验证前不降低窗口 minWidth。

### 3.2 悬浮条线框

```text
┌──────────────────────────────────────────────────────┐
│ ⋮  CODEX   29% 周余   ◔ 25.4% 风险    ▱ ×3     [⌄]  │
└──────────────────────────────────────────────────────┘
  拖动/品牌   主读数       次级读数       卡数     展开
```

- 从左到右：专用拖动把手、品牌、周余额、24h 模型风险、卡数、展开按钮。
- 周余额最大且最亮。风险旁可访问名称包含“未来24小时强制重置模型估计”；完整标签在预览/展开态出现。
- 卡数 null 显示“卡 —”，0 显示“卡 ×0”；不能照搬 cardPlan.credits 的默认零值。
- 数字区域不承担拖动。展开按钮至少 44×44 命中区域，其余文字区可提供预览且不会消费拖动事件。
- 公告有效时品牌边加状态标记，并提供可访问文本，预览/展开读正文；采集异常标记带可访问文本，不依赖色点。
- 不在悬浮条塞进短窗、四因子、更新时间全量文本；这些信息在下一层完整可达。

### 3.3 迷你预览线框

```text
┌──────────────────────────────────────────────────────┐
│ ⋮  CODEX   29% 周余   ◔ 25.4% 风险    ▱ ×3     [⌄]  │
├──────────────────────────────────────────────────────┤
│ 今日建议追加      +8.7 个周额度百分点                 │
│ 用卡建议           等待最佳用卡日                     │
│ 额度观测 10/11 09:18 北京时间       [查看完整规划 →]  │
└──────────────────────────────────────────────────────┘
```

数字仅为独立视觉示例，不声称对应当前账户或同一真实计算快照。图稿和截图若使用示例必须标“演示数据”。正式运行由同一 VM 全量替换。

有公告时第二行换成“公告计划 · 北京时间 MM/DD HH:mm”，用卡建议移入完整面板；stale 时保留数字并加“上次观测，正在刷新/刷新失败”。不为旧快照显示实时活动动词。

首屏至少容纳顶栏、状态摘要、余额、今日建议以及风险区域开头；完整解释和规划可纵向滚动。收起和关闭不在滚动区尾部。状态横幅变长时允许占据更多首屏，不裁掉按钮。

### 3.5 图表与解释规则

- 周余/短窗条各自是 0–100 的剩余比例，旁边永远有数字与标签。
- 因子默认呈现正负 delta 和 label；note 由行内说明展开。所有 factor 均从数组渲染，含零、负值与未来新增因子。
- 本次用因子列表和短条形提示替代完整瀑布图，避免将 clamping/舍入后的最终分数画成严格加法等式。
- 配速图使用 factors 的实际贡献与最终 suggested；cap 用边界线/约束标签。UI 不实现 min、风险平方或清仓算法。
- 候选日收益图用 outlook 原值生成柱长、顺序使用已有 localDate；最佳日标记按 bestDayLocalDate，日期用北京日历语义。最多约七条同时可见，其余纵向展开；旁边可切换文本表格。
- 期望收益为周额度百分点，不能写成“获得更多实际额度的承诺”。没有候选日时不画虚构柱形。

## 4. 视觉规范

视觉待参考图稿。AI 可自由选择配色、风格、字体与材质；前端按用户选中的图稿还原视觉表达。当前不规定色值、主题默认值、字体栈、圆角或阴影参数。

- 文字与其实际背景的对比度至少 4.5:1；非文字图形及焦点指示与相邻颜色的对比度至少 3:1，实施时按实际组合核验。
- 状态不能只靠颜色区分；同时提供文字、形状、图标或其他可感知线索。
- SVG 图标保持视觉一致，并提供合适的可访问语义；纯装饰图标对辅助技术隐藏，交互图标有可访问名称。

历史注记：旧稿所列色值的对比度复核曾得到最低 5.31:1。该结果只描述旧稿色值，不构成当前配色、风格或图稿的限制；选定图稿后仍按实际颜色组合重新核验上述可访问性要求。

## 5. 交互与微动效

| 动作 | 时序 / 反馈 | 边界 |
|---|---|---|
| 悬浮预览 | 指针停留 350ms 后出现 | 离开整个条+预览区域 200ms 后收回，移入预览不闪退 |
| 键盘预览 | 聚焦摘要后使用相同内容，展开按钮 Enter/Space 锁定全文 | 不主动抢系统焦点；focus离开组件后关闭短暂预览 |
| 点击展开 | 内容 opacity + transform 180ms；收起 140ms | 先给新内容分配足够窗口空间；收起内容退出后再缩窗，避免裁切 |
| 状态刷新 | 小型旋转标识，只在已知 in-flight 时显示 | 非确定进度不显示百分比；不让模型风险数字呼吸 |
| 按钮 hover/press | 背景/描边 120ms，press 最多 1px 位移 | visible focus 不被 hover 替代 |
| 复制摘要 | 原位“已复制”约 1.5s | 失败给明确反馈，不静默成功 |
| 视觉状态变化 | 按选中图稿实现 | 不改变业务状态语义 |

`prefers-reduced-motion` 下取消位移、旋转和持续骨架闪烁，用静态“刷新中”；保留立即状态反馈。无滚轮数字、循环雷达扫光、大幅弹簧伸缩。

内部采用明确展示状态 collapsed / peek / expanded；hover timeout、focus、click 只改变展示状态，不能触发重新计算业务建议。窗口几何与内容过渡的执行顺序集中管理，防止 resize observer 与 setSize 互相循环。

Escape：展开态收起，预览态关闭预览；焦点回到展开入口。关闭按钮隐藏到系统托盘，文字说明为“隐藏到托盘”；托盘菜单可唤回窗口或彻底退出。迷你圆点击先打开悬浮条，再点击悬浮条展开完整面板；收起及自动收起回到迷你圆。如选中图稿包含主题控制，菜单可有自身焦点约束；整个展开面板不是模态，不强行锁住系统焦点。

窗口保留启动 `focus:false` 以免抢焦点，并明确 `focusable:true`。本地Tauri CLI schema将focus定义为“最初是否聚焦”，与“能否获得焦点”的focusable是两个属性。用户激活窗口后可Tab导航；hover不会主动setFocus。阶段4必须在真实窗口验证点击激活、Tab、Escape与焦点返回，不能只用浏览器DOM验证替代。

拖动只在把手/非交互标题区启用，button、链接和图表操作区域明确排除拖动。扩展窗口定位使用工作区边界进行夹紧；需要时向上展开，同一逻辑尺寸统一转换，不硬编码当前机器 200% 缩放倍数。

## 6. 全状态设计

采集生命周期与数据时效是两条独立状态轴；例如 stale + 刷新失败同时存在。不能把它们压成互斥单枚举。优先级：已知有效公告提示 → 失败/stale 来源提示 → 正常内容；关键提示可同时存在。

| 情况 | 悬浮 / 预览 | 展开内容 | 可用操作 / 数字语义 |
|---|---|---|---|
| 首次加载、无快照 | 保持条形壳，品牌+骨架+“读取中” | 固定分区骨架，简短首次读取说明 | 保留关闭；不呈现模拟余额，不做假进度 |
| 读取成功但空数组 | 周余 —，文案“暂无额度数据” | 空态小图标、“未取得 Codex 额度快照” | 刷新额度；原因未知时不推断为未登录 |
| 首次 invoke失败、无可用快照 | 周余 — + 错误标识 | “读取失败”，可读原因，不用纯英文异常占满面板 | 刷新额度、关闭；长技术细节置可展开区域 |
| listen订阅失败但已有读取结果 | 保留有效额度，提示“自动更新不可用” | 数据正常显示，自动更新错误作为独立横幅 | 手动刷新额度；不因订阅失败清空所有快照 |
| 后续读取失败、有旧快照 | 数字保留，加“上次观测” | 错误横幅 + 旧值 + 完整观测日期时间 | 刷新额度；copy摘要含旧值状态 |
| stale、后台刷新中 | 旧值+stale文本；有真实in-flight才显示刷新标识 | “数据过期，正在刷新”，旧建议标“基于上次观测” | 不把过期建议称为当前实时行动 |
| stale、刷新结果未知 | 旧值+“数据过期” | 观测时刻与状态 message；不自行添“正在刷新” | 刷新额度 |
| 正常且数据完整 | 常规条+预览 | 正常信息顺序 | 复制/解释/规划 |
| 周窗缺失 | 周余 —；风险如有可单独显示 | 周窗缺失的局部提示，今日建议/规划占位 | 不用短窗代替周窗 |
| shortRemainingPercent null | 主条不受影响 | 短窗 —，注明暂无数据 | 不写 0% |
| dailyPlan/cardPlan null | 预览不输出建议数字 | “当前无法生成建议/规划”，说明已知缺项 | null也可能来自无效/已过自然重置时刻，不能一律写“缺周窗” |
| resetCredits null | 卡 — | “卡数未知，暂无法确认用卡建议”；隐藏核心回退no-credits的决策及对应收益比较/候选收益图 | 其他额度、风险、配速及已知重置时刻仍可读，不能仅改卡数文字而保留“无卡”决策 |
| resetCredits 0 | 卡 ×0 | “无可用重置卡”；保留风险与今日配速 | 无自动用卡入口 |
| 余额确为 0% | 显示 0%，不使用 — | 建议由核心输出；用卡建议按decision显示 | 零和缺失严格区分 |
| 有计划重置公告 | 条上公告标记，预览显示计划时刻 | 展开顶端公告来源/时间/状态；模型读数另列 | 倒计时仅格式化日期，建议策略由RR22核心输出 |
| 公告时刻已过未确认事件 | 标“公告待核实”或数据层给出的准确状态 | 保留公告时刻，明确尚未确认发生 | 不写“额度已回满”或自行刷新所有计划假设 |
| 公告拉取失败/过期 | 额度正常仍可显示，公告区域标未更新 | 单独显示公告来源状态 | 不把“无最新公告数据”写成“没有公告” |
| 校准 n=0 | 不进入主条 | “数据积累中”，样本量0；分数 — | 不生成趋势或伪造命中率 |
| 浏览器预览 demo | 可见“演示”标识 | 显示“演示数据 · 非本机实采” | 复制摘要同样标演示，绝不冒充实跑证据 |

时间一律显式格式化为北京时间（Asia/Shanghai），跨日包含日期；禁止截 ISO 字符串再标“北京+8”。相对时间仅是显示格式；stale 判定由数据/adapter明确提供，不在组件设未经证据核实的过期分钟数。

## 7. 数据契约与实现边界

### 7.1 现有字段映射

| UI | 唯一数据入口 |
|---|---|
| 品牌 / 方案 / 采集消息 | VM.displayName / plan / status / message |
| 周余 / 短窗 / 原始卡数 | VM.remainingPercent / shortRemainingPercent / resetCredits |
| 24h模型风险 / 解释 | VM.risk.score / factors（含id,label,delta,note） |
| 今日追加、上限、均匀、前拉、建议后剩余 | VM.dailyPlan.suggested / cap / uniformPace / riskBoost / suggestedRemaining |
| 用卡决策 / 原因 | VM.cardPlan.decision / reasons，UI中文映射 |
| 今日与最佳日收益 / 日期 / 候选日图 | VM.cardPlan.expectedGainTodayPercent / expectedGainBestPercent / bestDayLocalDate / outlook |
| 48h碰撞 / 自然重置 | VM.cardPlan.forcedReset48hPercent / daysUntilNaturalReset；自然时刻VM.resetsAt |
| 观测时间 / 本地更新 | VM.observedAt / updatedAt |

保留今天24h碰撞、补给规模、日需假设、策略版本、完整理由等已有字段，在“规划依据/数据详情”中可读，不删功能。risk.score 和 cardPlan.forcedReset24hPercent 可能因模型时段口径而不同；分别命名，禁止互相覆盖或把48h简单翻倍。

### 7.2 必须补足的契约（目标，当前尚未实现）

- useSnapshots 增加真实生命周期：初始化中、空返回、读取错误、是否正在请求；现有 catch 静默且忽略空数组，无法正确呈现全状态。适配后的 UI状态类型可独立于 VM，但所有业务数字仍只来自 VM。
- 初始读取继续get_snapshots的SWR语义；手动“刷新额度”调用refresh_snapshots，已存在于src-tauri/src/lib.rs。请求完成不代表数据有效，仍检查返回status/message；事件订阅失败单独提示“自动更新不可用”，手动刷新成功时仍可展示数据。
- 公告元信息：RR23 原始 scheduled_reset/active_watch 进入数据层；RR22 输出核心业务结果；adapter 统一映射公告计划时间、状态、文本、来源、抓取时刻和有效性。前端不直连第三方接口，不以公告字段自行算清仓配速。
- 时间来源：额度 observedAt、快照 updatedAt、历史 fetchedAt、公告 fetchedAt 各有独立元信息。历史时刻当前不在VM，必须由历史载入元数据透传。
- 校准只读摘要：计分样本数、Brier、命中率、报告时刻/覆盖范围、来源状态。通过最小只读桥接读取真实计分结果；可空且后向兼容。不在React实现另一份评分算法，不把风险分显示成置信度。
- stale 元信息由各数据源带出，主题与数字格式化不决定业务有效性。显示未知状态比编造“新鲜”准确。

新字段在相应卡内写清类型、默认值、生产来源和缺失行为，并有契约验证；正式UI组件消费 adapter/展示状态，不从Rust原始快照另取数字绕开VM。

### 7.3 样式与组件方案

样式组织可采用 CSS Modules + 全局 CSS 变量，便于按选中图稿集中实现视觉样式、局部布局、状态样式和 reduced-motion。继续React 19 / TypeScript / Vite，不换框架。

建议组件为 WidgetShell、CompactBar、PeekCard、DashboardPanel、StatusNotice、QuotaSummary、DailyUsageSection、RiskSection、CardPlannerSection、DataDetails、Metric、IconButton；边界以复用/状态责任为准，不为每个数字拆独立组件。

窗口几何与Tauri命令集中在 widgetWindow；useSnapshots负责数据生命周期；adapters承担唯一业务VM装配；src/lib保持唯一业务算法。前端生命周期修正可能涉及src/App.tsx与useSnapshots，不能只改src/ui目录后遗留旧接线。
