# reset-radar v3.2：星期效应算法提案与证据评估

日期：2026-10-13（北京时间）  
卡号：RR54；基线提交：`bdebb34`（包含 v3.1 与 RR53 内存修复）。  
交付性质：**可实施提案、隔离算法原型与可复现历史实算。未接入正在运行的程序，未启用线上星期影子，未更换 D60 默认，未发布。**

## 1. 决策

建议加入一个固定参数的 **D60-W28-BJT 星期影子模型**：沿用 D60 的时间衰减，用北京时间划分七个星期，对各星期发生率向 D60 强收缩，再按未来窗口实际经过的星期积分。先冻结预测、配对评分，达到预定门槛后才考虑转为默认参考。

现有证据支持“值得低成本验证”，不支持“周二、周六已证明更危险”，也不能据此断言目前约 20% 的概率偏低。概率更高不是预测质量指标。现有数据中周日也突出，不能因用户先想到周二、周六便忽略周日。

本提案对 v3 §3.1 的修订范围很窄：**允许未验证星期特征进入隔离实验，不撤销当时证据不足的判断。** v3.1 的 60 天半衰期、7 等效日总体收缩保持不变。星期参数不会进入当前用卡建议或账号到账概率。

### 2.3 “1.47倍”是什么、不是什么

近180天的 `8 / (38/7)＝1.4737` 是事件份额相对均匀份额的倍数；周六为 `7/(38/7)＝1.2895`。它还没有校正各星期的观察时长、边缘半天、近期衰减、覆盖空档和估计不确定性，不能直接作为模型参数。

发生率也不等于概率。即使暂且假定整个24小时发生率都乘1.47，若 D60 概率恰为20%，则：

```text
lambda = -ln(1-0.20)
p_new = 1-exp(-1.47*lambda) = 1-0.8^1.47 ≈ 28.0%
```

`20%×1.47＝29.4%` 是另一种、不采用的计算。用户“约27%”可作为近似示意，不作为验收目标。正式候选还要强收缩、整周归一化并跨午夜积分，提升通常更小，也可能下降。

选择 **Asia/Shanghai** 作为唯一第一候选，原因是它是 v3 已有日键、星期、09:00发布和用户工作周的预先约定，不增加一个从这54条里挑赢家的自由度。UTC 时间戳只是存储方式；本轮未发现可证明“平台按 UTC 星期排程”的机制证据。美西时区也没有经验证的排程依据，不能因为平台团队可能在某地就推断机制。美西夏令时须由 IANA 时区换算，不能全年固定 UTC−8。

这是保守的实验设计选择，**不是发现北京时区最真实、最优**。其他两时区只作描述性敏感性检查，不同时开三个可随时转正的候选。未来若有外部排程机制证据，要新版本、重新预定验证期，不能回头选当前分数最高的时区。

你的规律工作周更直接影响个人消耗、额度见底和何时需要用卡；这些属于需求与规划层。它不会因果上提高平台全体 regular 公告的发生率。v3.2 本候选只预测平台公告；个人工作周将来可在需求模型中单独验证，不能把它混成“我的账号周二一定到账”。

## 4. 唯一候选的算法定义

### 4.1 目标、输入与固定参数

目标仍是未来 `(t,t+h]` 至少一次 regular **公告**。banked、个人用卡、自然重置不进入平台事件分子；ID/关联事件去重、版本可见性、完整覆盖均沿用 v3.1。

| 参数 | 固定值 | 含义与依据 |
|---|---:|---|
| D60 半衰期 | 60天 | 沿用 v3.1 工程默认 |
| D60 总体收缩 | 7等效日 | 沿用 v3.1，不意味着七天周期 |
| 星期收缩 τw | **每个星期28等效观察日** | 本提案预定的强正则化，非历史寻优结果 |
| 星期时区 | Asia/Shanghai | 沿用既有时间语义，非挑最高峰 |

注意：每个星期28天意味着七组总计196等效暴露日，不是总计28天再分七份，也不是只取最近28个日历日。七个星期一视同仁；没有“周二/周六奖励常数”、手填1.47、固定周期或额外年龄项。新增的是一组受强约束的六个相对自由度，只有一个新的收缩档位参数；不叠加月份、钟点或工作日交互。

### 4.2 加权计数与加权暴露

在预测截点 t 固定 `w(t,u)=exp[-ln(2)*(t-u)/60天]`，令 `d(u)` 为北京时间星期，`C` 为可靠覆盖区间并集：

```text
C_d = Σ w(t,event_i) · 1[d(event_i)=d]       # 仅可见且在覆盖内的规范regular
E_d = ∫_C w(t,u) · 1[d(u)=d] du            # 单位：天
lambda = 原实现 fitTrendModel(input).ratePerDay

q_d = (C_d + 28*lambda) / (E_d + 28)
q_bar = (q_日 + ... + q_六)/7
m_d = q_d/q_bar
lambda_d = lambda*m_d
```

所有覆盖区间先合并、截在 t，再在每个北京时间午夜切段，用 D60 已有指数积分精确求暴露，不用“每个星期都恰好总天数/7”的近似。事件与分母须用同一覆盖范围，尾段无事件时间照算。`ΣC_d=Cw`、`ΣE_d=Ew` 是必须测试的不变量。

τw 让小样本星期的率向整体率收缩。例如一星期的加权暴露约12天时，观测局部率的权重只有 `12/(12+28)≈30%`。这是平滑估计：同批历史也参与 D60 中心，不宣称独立贝叶斯先验或精确后验可信区间。

采用七个星期等权算术归一化，使 `Σm_d/7=1`，冻结率下任意完整七天的累计风险强度恰好等于 `7*lambda`，防止“加星期特征”偷偷抬高整周总率。它不要求衰减加权训练暴露的平均拟合率也恰好不变；二者权重不同，此处明确保未来整周强度。

若总体率为0且覆盖有效，乘数设1、概率0；若总体率未知，输出未知并回退 D60 原有降级。不能把未知变为零。

### 4.3 未来窗口按实际经过的星期积分

```text
H(t,h) = Σ_segments lambda_{weekday(segment)} * segmentDurationDays
p(t,h) = 1-exp[-H(t,h)]
```

拟合参数在一次预测中冻结，分段只因未来北京时间午夜变化。周二09:00的24h预测是周二15小时＋周三9小时；周六晚上则主要包含周日。不能拿起点星期的系数覆盖整个24小时，更不能拿周二自然日的事件份额解释所有周二发出的预测。

版本固定为 `platform-v3.2:D60-W28-BJT-shadow`。任何改变 τw、时区、公式、数据可知性或目标窗口的实验都另开版本；不得把更新后的预测回填旧时间戳。

### 5.4 你的“偏低”直觉是否完全没有依据？

不是。0h理想化回放中，D60累计预测概率之和/实际正例数，全期为0.663、近180天0.706、近90天0.787，提示这些历史评估日上存在整体低估倾向；W28分别为0.664、0.707、0.787，基本没有改善。这个诊断值得保留，不能因为星期证据弱就把它忽略。

但它不能证明“今晚20%应该是多少”：这是理想化历史总体校准、非同一时刻的真概率；时期变化、可见性和采样都可能影响它。星期模型重排周内强度，并不修复整体率滞后。如果未来独立评分仍确认总体低估，应另立“总体校准/趋势适应”候选，与星期实验分开定档和比较；不把这轮回放的实际/预测比直接乘到在线概率，也不临时缩短半衰期追高数值。

## 6. 证据强度判断

| 命题 | 本轮判断 |
|---|---|
| 这批公开历史里的星期计数不相同 | 可复核事实 |
| 近180天周二/周六份额高于2/7 | 可复核描述，周日同样突出 |
| 周二/周六具有稳定、可迁移的未来规律 | 证据弱，尚未证明 |
| 加星期项可以提高未来预测质量 | 待前瞻配对验证 |
| 用户工作周能解释平台公告排程 | 无机制证据，不这样推断 |
| 当前20%应当人为提高到27% | 不支持作为目标或验收标准 |

弱证据不意味着禁止一切尝试；合理响应是低自由度、强收缩、可撤回的实验。反过来，p值不显著也不应被表述为星期效应必为零。

需要同时承认：星期/窗口/时区已有事后选择；事件可能相关；历史 firstSeen 缺失；公开公告与实际账号补给不是一个目标；近期样本很少；平台策略可变。7/14日分块只能缓解短期依赖，不能消除选择偏差或保证跨月稳定。不会给这些数据编造“规律成立概率”或精确置信等级。

## 7. 影子发布、计分与转正方案

### 7.1 先接日志，后谈上线验证

影子启用当天冻结上述版本和本节规则，D60 主参考继续显示并驱动规划。同期追加星期候选的原始概率；记录 `C_d/E_d/m_d`、总体率、收缩档位、时区、训练截点、历史快照ID、未来分段、假设和证据质量。旧 D60/P0/P1/R90 行保持不变。

同一次发布同时保存 D60 和星期候选。只比较同目标、同 `issuedAt/trainingCutoff/windowStart/windowEnd/historySnapshotId` 的成对记录，且标签一致。按模型/版本/日去重；记录坏行、缺配对、未知、待成熟和覆盖不足的数量。禁止拿两模型各自不同样本的汇总 Brier 相减。

沿用北京时间09:00实际发布的 `primary_daily`，窗口恰为24小时；App 未运行则记缺失，不回补。其余刷新属于 `temporary`，不增加转正样本。已成熟且有完整覆盖才能把无事件记为负例；迟到事件/修订只追加新版 verdict，评分使用最新有效标签，不能改旧预测。

主比较对象必须是 **D60**，P0只作长期参照。不能只胜过较弱的 P0 便宣布星期模型改进了 v3.1。主指标 Brier，辅助对数损失、预测/实际比例与粗分箱校准；全体成对日和全部星期都报告，不能只在周二/周六打分。采用这些概率评分的依据是其对诚实概率预测的激励，而不是追求更多高概率提示。[Gneiting 与 Raftery，2007](https://sites.stat.washington.edu/people/raftery/Research/PDF/Gneiting2007jasa.pdf)。

### 7.2 预定评审日，避免每天等一个“显著”结果

建议第一实验版本只设启用后第90、180、365天三个正式转正评审点，均使用从启用起累计的成熟成对样本。日常可看分数、做故障检查，但不因某一天表现好提前转正。到点不足则记录不足，等下一个预定点；365天仍不满足则维持未验证，续实验需新登记规则。

转正需同时满足以下工程门槛，且仍须人工审阅版本与覆盖：

1. 至少60个有效固定日配对、至少10个正例、覆盖至少12个不同北京时间日历周；这些只是样本下限。
2. 累计 `Δ=Brier(D60)-Brier(W28)>0`。
3. 预定7日与14日整块配对重采样均支持改善，不可仅一小段连发支撑。正式评审以10,000次固定种子重采样，计算约98.33%双侧区间（对应三个预定查看时点的保守Bonferroni分配），两种块长下限均须大于0；首尾不完整块和有效块数明确报告。历史实算中的95%描述区间不替代此门槛。
4. 同批对数损失不高于 D60；按时间段和星期拆分展示，校准没有集中于某一时期的明显恶化；存在无法解释的偏差则继续影子，不以小样本分箱作“已校准”证明。
5. 日志与结算链真实工作，无泄漏、补写预测、错配窗口或未知当负例；历史回放不能计入这60个在线日。

上述区间和多次查看控制在相关、非平稳小样本下仍是近似工程方法，不承诺严格的误报率保证；满足门槛表示达到评审资格，不等于机制被证明。固定阈值不来自本次回放挑选。

### 7.3 停用、回滚及规划边界

影子出现非有限概率、覆盖错误或写入异常，立即停止该候选写入并记录故障，保留 D60。统计变差时保留记录如实评估，不反复换档直到变好。

若以后转正，保留 D60 及同样配对日志作为回滚参照。沿用 v3.1 的工程止损形式：最近28个成熟配对日足量、星期模型 Brier 比 D60 差超过0.01，并在连续两次每周审阅中成立时提出回滚。阈值是运营护栏，不是显著性证明。

在转正前不改变用卡模拟器、三组费率敏感性或个人到账映射。转正时还须把平台路径生成器改为同一分段强度，保持共同随机数、前缀稳定、资源界限和RR53内存护栏；不能只让面板数字带星期、规划仍用常数率，却声称二者一致。平台→账号的映射证据要求也不因星期模型得分较好而放宽。
