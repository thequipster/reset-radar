# 01｜悬浮条呈现候选（阶段1发散稿）

> 存放说明：本文件由 RR26 正式落档于仓内 docs/design/01-proposals.md。以下保留阶段1候选历史，均未因此自动成为视觉定稿或实现承诺。

> 这是候选创意池，逐条保持未选定状态；不构成视觉方案定稿或实现承诺。所有超出现有类型/算法输出的想法，均明确标成新增能力依赖。阶段1候选历史保留于此；阶段2规格见 docs/design/02-spec.md，后续视觉以用户选定图稿为准。

## 候选提案

### 01. 周额度优先的紧凑悬浮条
- 创意：把 provider 名称、周窗剩余百分比作为视觉主轴，卡数和风险收成次级徽标；展开后再展示解释。
- 解决：让悬浮态一眼回答“还剩多少”，并减少狭窄窗口里的横向争抢。
- 支撑：`DashboardViewModel.remainingPercent`、`displayName`、`resetCredits`、`risk.score`；余额来自周窗，保留“周”单位标签。

### 02. 可 hover、可键盘触达的迷你预览
- 创意：鼠标悬停短暂展开迷你提示，键盘聚焦时提供同样摘要，鼠标离开后收回。
- 解决：不用点开完整面板也能看懂风险和下一步建议，并让键盘用户可发现内容。
- 支撑：已有余额、风险和建议字段；hover/focus 状态为 UI 能力，须实现焦点管理与可访问名称。

### 03. 点击展开的“今日追加建议”Hero
- 创意：展开首屏以大号数字展示今日建议追加百分点，紧邻周剩余和一句建议解释。
- 解决：把当前最可执行的动作从多组指标中突出出来。
- 支撑：`dailyPlan.suggested`、`suggestedRemaining`、`remainingPercent`、`factors`；`suggested` 是建议追加量，不是今日总用量。

### 04. 周额度与重置风险双色分区
- 创意：周余额使用青绿系，强制重置风险使用独立琥珀/珊瑚系，并让颜色只对应一个语义。
- 解决：避免把“额度还剩多少”和“未来重置可能性”误看成同一种进度。
- 支撑：`remainingPercent` 与 `risk.score`；色板与深浅主题是新增 UI 设计能力，颜色不能单独承载含义。

### 05. 带正负号的因子瀑布图
- 创意：按因子次序绘制从基线到最终风险分的正负百分点变化，负贡献向左/向下，正贡献向右/向上。
- 解决：解释风险分怎样从启发式基线变化，避免因子数字被误解成独立概率。
- 支撑：`risk.factors[].label/delta/note` 和 `risk.score`；delta 为百分点，浮点舍入后总和可能略有差异；需 UI 图形组件。

### 06. 配速、风险前拉和软上限关系图
- 创意：显示均匀配速基线、风险前拉后的中间量、最终建议与软上限边界；软上限画成约束线/削减段，不作为加项。
- 解决：让用户看懂为何最终建议可能低于“均匀配速 + 风险前拉”。
- 支撑：`dailyPlan.uniformPace/riskBoost/cap/suggested/factors`；核心关系为 `min(remaining, uniformPace + riskBoost, softCap)`，cap 不是需要再加到建议上的量。

### 07. 用卡日期收益条形图
- 创意：以日期为横轴、期望额外消耗周额度百分点为条长，当前日和模型最佳日做颜色标记。
- 解决：将“等哪天用卡”的判断变成可比较的时间序列。
- 支撑：`cardPlan.outlook[].localDate/expectedGainPercent/refillPercent/resetWithin24hPercent`；期望收益是模型估计，不是保证收益。

### 08. 今天 vs 最佳日期双卡比较
- 创意：并排呈现今天预计收益、最佳日预计收益、两组百分点数值与最佳日期，附决策理由短句。
- 解决：避免只告诉用户“等待”却不展示等待带来的预期差别。
- 支撑：`expectedGainTodayPercent`、`expectedGainBestPercent`、`bestDayLocalDate`、`decision`、`reasons`；理由机器键需 UI 文案表。

### 09. 自然重置与强制重置分轨
- 创意：时间轴上用固定刻度标自然周重置，用概率带/风险标记表示未来强制重置窗口。
- 解决：澄清自然周期到期与随机强制重置是两种不同事件。
- 支撑：自然重置时刻 `resetsAt`、`daysUntilNaturalReset`；强制重置 `forcedReset24hPercent/forcedReset48hPercent`；若要未来多日概率曲线，依赖扩展核心输出。

### 10. 未知卡数和确知零张分开
- 创意：卡数缺失时显示“卡数未知”，确认为零时显示“0 张”，避免同一个空状态。
- 解决：防止把上游没有提供卡数误解成账户没有卡。
- 支撑：`ProviderSnapshot.resetCredits: number | null`；当前 `planResetCard` 会把 null 归成 credits=0/no-credits；展示可直接依据 VM.resetCredits 的 null/0 区分，并避免卡数未知时展示“无卡”的确定结论。若要改变核心决策则另立核心卡。

### 11. 首次加载骨架
- 创意：首次快照尚未到达时显示小型占位骨架，维持悬浮条形状，不用空白闪屏。
- 解决：降低启动时内容突然出现造成的闪烁感。
- 支撑：现有 `status/message` 可承载部分加载文案；可靠区分“尚未加载”需增加 loading 状态或快照生命周期字段。

### 12. 失败态保持明确但克制
- 创意：失败时展示简短原因、最近一次成功观测时间和重试入口，主余额保留旧值并加“上次成功”标记。
- 解决：既能看出更新失败，也不把旧余额伪装成实时值。
- 支撑：`status/message/observedAt/updatedAt`；自动重试和最近成功快照保留策略需要采集层新增状态/行为。

### 13. 部分字段缺失时按区块降级
- 创意：某个窗口、卡数或计划缺数据时只隐藏/替换对应区块，其他可信字段继续展示。
- 解决：避免一项缺失导致整个面板消失或错误显示为零。
- 支撑：`weeklyWindow/shortWindow/resetCredits` 可空，VM 中计划可空；具体区块空态文案属 UI。

### 14. stale 时保留旧值并标注时效
- 创意：数据变 stale 后保留最近一次额度数字，旁边持续显示 stale 标记与观测时间，不突然清空数字。
- 解决：让短暂采集故障时仍有参考，同时降低误以为数据新鲜的风险。
- 支撑：`status/message/observedAt/updatedAt`；截图中已见 stale 状态；需确认数据层是否始终保留上次成功快照。

### 15. “观测时间”与“刷新/更新时间”分开
- 创意：用“额度观测于…”表示上游额度时间，用“本地快照更新于…”表示本地更新时间；对历史风险数据另列来源时刻。
- 解决：避免把不同数据的时间戳混成一个“更新时间”。
- 支撑：`RateLimitSnapshot.observedAt`、`ProviderSnapshot.updatedAt`；明确限制：`observedAt` 是额度观测时间；VM 没有历史夹具 fetchedAt，历史数据新鲜度需另加字段，不能拿额度观测时间冒充。

### 16. 数字位数轻量变化动画
- 创意：余额或建议数变化时做短促数字滚动/交叉淡入，减少刷新跳变。
- 解决：提升更新可感知性，同时保留数字连续性。
- 支撑：现有数值字段足够；动画状态是 UI 能力，不代表补齐了新的数据精度。

### 17. 尊重 reduced-motion
- 创意：系统启用减少动态效果时，数字变化改为静态替换，展开与收起不做位移动画。
- 解决：照顾对动态效果敏感的用户。
- 支撑：UI 读取系统无障碍偏好即可，不需新增业务字段；属新增前端体验能力。

### 18. 拖动区与点击控件分开
- 创意：仅标题/专用把手区域用于拖动窗口，展开、复制、关闭、风险详情控件各自保留点击区域。
- 解决：避免点按钮时误拖整窗，也避免不能操作拖动区域。
- 支撑：无业务字段依赖；需要 Tauri 窗口拖动命令与前端事件区域设计。D021 仅裁决了需有拖动区方向。

### 19. 收起与关闭动作有清楚区别
- 创意：收起回迷你条，关闭隐藏/退出单独处理；两者采用不同图标、标签和键盘操作。
- 解决：降低用户误关窗口、误以为关闭只是收起的风险。
- 支撑：UI 交互状态与 Tauri 窗口生命周期能力；现有输出类型不决定窗口行为。

### 20. 靠近屏幕边缘时自动翻向
- 创意：展开面板在悬浮条靠近右/下边缘时向左/上展开，尽量留在工作区内。
- 解决：减少展开内容超出屏幕边缘而无法阅读或点击。
- 支撑：Tauri 窗口位置/屏幕可用区域查询及动态定位能力；不依赖额度字段，属于新增桌面能力。

### 21. 键盘导航与可见焦点
- 创意：支持 Tab 到展开/收起、摘要、复制和关闭；焦点边框清楚，Escape 收起面板。
- 解决：让不使用鼠标的用户能完整操作悬浮条。
- 支撑：现有 UI 控件状态；需要补焦点顺序、快捷键和无障碍标签。

### 22. 深色石墨青绿方向
- 创意：以石墨背景、青绿余额、低饱和中性说明文字构成安静的常驻工具感。
- 解决：减少长时间悬浮造成的视觉负担，同时突出剩余额度。
- 支撑：数值依赖 `remainingPercent`；颜色纯属视觉方向候选，需检查对比度并为风险另配语义色。

### 23. 浅色纸面方向
- 创意：采用暖白纸面、细线分组、墨色数字和克制的强调色，让面板更接近桌面便笺。
- 解决：给偏好浅色桌面的用户一个不突兀的常驻阅读面板。
- 支撑：现有数据字段无需变化；主题切换/跟随系统是新增 UI 偏好能力。

### 24. 琥珀仪表板方向
- 创意：以深色仪表盘配琥珀风险标记和清楚刻度，弱化装饰，强化风险变化线索。
- 解决：让风险读数更醒目，同时避免与额度色混淆。
- 支撑：`risk.score/factors` 和周余额；视觉色义仍是候选，不暗示风险分已具备统计校准。

### 25. 统一 SVG 图标组
- 创意：为周额度、短窗、卡片、强制重置、自然重置、时间和信息说明建立同一笔画风格的 SVG 图标。
- 解决：减少纯文字标签拥挤，并帮助快速扫描。
- 支撑：现有字段分别是 `remainingPercent`、`shortRemainingPercent`、`resetCredits`、风险和重置时刻；需新增图标资产/组件，图标旁仍需保留文字或可访问标签。

### 26. 每个数值旁固定单位标签
- 创意：明确标出“周剩余 %”“短窗剩余 %”“今日建议追加百分点”“风险分 %”“期望收益百分点”。
- 解决：防止多个百分数因为单位不同而被比较错。
- 支撑：VM 与 planner/cardPlan 字段；标签需要准确反映各字段口径，不能统一简写成“%”。

### 27. 一键复制简短状态摘要
- 创意：复制如“周额度剩 29%；今日建议追加 8.7 个百分点；24h 重置风险分 25.4；观测于 09:18”的摘要。
- 解决：便于用户贴进笔记或和他人讨论当前状态。
- 支撑：`remainingPercent/dailyPlan.suggested/risk.score/observedAt`；复制为新增 UI 动作，文案需把风险明确称为模型风险分。

### 28. 隐私模糊模式
- 创意：快捷键或按钮将余额、风险和卡数模糊/隐藏，保留窗口结构与状态灯。
- 解决：屏幕共享或旁人经过时减少敏感额度信息暴露。
- 支撑：本地 UI 显示开关，不需要服务端字段；若跨重启记忆，依赖新增本地偏好存储。

### 29. 真实日消耗轨迹
- 创意：按日画出实际观察到的周额度消耗与建议区间，区分观测点和预测线。
- 解决：帮助用户判断默认均匀配速是否符合自己的使用节奏。
- 支撑：目前 `estimateDailyNeedPercent` 接受 `DailyNeedSample`（日期、观测消耗、样本数），但 adapters 传空数组并用 `100/7` 兜底；要显示真实轨迹需采集并持久化日消耗样本，属新增数据能力。

### 30. What-if 风险情景滑杆
- 创意：提供“若未来24h风险为 X”情景滑杆，实时预览今日建议和剩余量，不改当前正式预测。
- 解决：让用户理解风险假设变化怎样影响建议。
- 支撑：`planDailyUsage` 接收风险输入；交互情景状态属 UI 新增能力；若要编辑真实模型风险或保存情景，需明确隔离并扩展数据/核心接口。

### 31. 用卡规划联动开关
- 创意：打开联动后，按计划用卡日缩短配速 horizon，并显示卡日前建议用量；关闭时维持自然重置配速。
- 解决：让今日建议和用卡计划彼此一致，避免各自独立阅读造成冲突。
- 支撑：`cardPlan.bestDayOffset`、`forcedResetBeforePlanPercent` 与 `planResetCardPacing` 已有纯核心入口；当前 `DashboardViewModel` 未暴露联动配速结果，需 adapter/UI 接线和用户开关状态。

### 32. 校准图附样本量与数据新鲜度
- 创意：展示校准曲线时同时标出样本量、时间范围和历史夹具 fetchedAt；样本不足则显示“数据积累中”。
- 解决：避免小样本或陈旧数据的漂亮曲线被误读为可靠结论。
- 支撑：校准报告/预测日志已有独立数据路径；当前 review 记录 n=0 且 as_of 停在历史夹具 fetchedAt；VM 没有历史 fetchedAt，需扩展校准数据读取和 UI。

### 33. 风险分数解释卡
- 创意：点开风险数字后显示基线、样本不足时未启用的因子、参与的因子以及“这是模型估计”的说明。
- 解决：减少把启发式百分数当成精确概率或单因素因果的误读。
- 支撑：`risk.score/factors`；当前 factors 仅包含实际参与的因子，样本门槛/缺席原因需要核心层额外诊断字段。

### 34. 额度观测与历史模型双时间线
- 创意：将上游额度观测时间与重置历史抓取时间并列，分别提示各自新鲜程度。
- 解决：用户能区分“额度刚更新”与“历史训练/风险数据较旧”。
- 支撑：`observedAt` 只对应额度观测；历史 `fetchedAt` 目前未进入 VM，需从历史数据元信息新增传递字段和 stale 策略。

### 35. 胶囊内的轻量刷新反馈
- 创意：后台刷新期间让状态点短暂呼吸或环形扫过，成功后回到静态；数据 stale 时保留稳定的告警标志。
- 解决：让用户知道正在刷新，同时避免频繁重绘整张面板。
- 支撑：`status/message/observedAt` 可提供状态依据；刷新过程状态/节流策略需采集层补足，动画遵循 reduced-motion。

### 36. 当前与短窗余额的双层刻度
- 创意：主条只显示周额度，展开后加一条较细短窗刻度，并分别显示其重置时刻或“暂无时刻”。
- 解决：避免把短窗余额和周余额混为一谈，也让短窗字段不只剩孤立数字。
- 支撑：`shortRemainingPercent` 已映射；短窗 `resetsAt/windowSeconds` 存在 `ProviderSnapshot.shortWindow`，但未进入 VM，需 adapter 扩展。

### 37. 有效数据遮罩与保留策略提示
- 创意：数据异常时对过期数值加轻微遮罩/斜线纹理，仍可读数字，旁边标明“上次有效值”。
- 解决：同时保留参考价值并避免旧数值看起来和新鲜值一样可信。
- 支撑：`status/observedAt`；需要可靠的最后一次有效快照语义或 freshness enum，不能只凭视觉推断。

### 38. 状态变化摘要而非无声跳数
- 创意：刷新后用一行描述“周剩余从 34% 变为 29%”或“状态已恢复”，用户可关闭该提示。
- 解决：让突发数值变化有上下文，避免用户把刷新变化误当渲染错误。
- 支撑：当前快照字段可与上一快照比较；需保留前值并定义变化阈值/隐私规则，属新增 UI 状态能力。

### 39. 安静时段与提醒强度控制
- 创意：允许设置提醒时段、提醒频率和风险阈值，默认不弹出打断性通知。
- 解决：让风险提醒贴合个人节奏，避免通知疲劳。
- 支撑：ROADMAP 已列系统通知方向；阈值/静默时段/通知权限是新增本地设置和桌面通知能力，不能视为当前已有功能。

### 40. 可解释的卡片到期提示
- 创意：在卡片确有到期时间时，把“预计最佳日”和“到期日”画在同一条时间轴；未知时明确写“上游未提供到期时间”。
- 解决：避免用户等待最佳日却忽略卡片可能先过期。
- 支撑：`daysUntilCreditExpiry` 可为空；adapter 当前固定 `creditExpiresAt: null`，真实到期提示依赖上游新增字段及 adapter 传递。

### 41. 无账户或完全空数据的引导卡
- 创意：空数据时保留同形工具壳，给出“未取得额度数据”的明确说明、可核实的采集原因和可用操作；所有数值显示占位，避免展示假零。
- 解决：让用户知道当前为何看不到数据、下一步能做什么。
- 支撑：VM 可空与 status/message；现有生命周期尚不能完整区分首次等待、未登录、空返回与失败，确切原因需要 hook/数据层提供，文案不靠猜测。

### 42. 位置记忆与临时停靠
- 创意：记住常用屏幕和悬浮位置，另提供贴边停靠和临时解除置顶；重启回到可见工作区。
- 解决：减少每次启动重新摆放，并降低悬浮窗遮挡编辑器的频率。
- 支撑：ROADMAP v0.3 已提出位置记忆；需要本地偏好存储、显示器变化处理和窗口命令，属于新增桌面能力。
