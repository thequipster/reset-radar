# reset-radar v3.1 算法修订提案

日期：2026-10-12（北京时间）  
依据：桌面《reset-radar-算法重设计规格-v3.md》及用户本轮上线反馈。  
性质：可实施的修订报告；未修改线上代码，未对原始事件数据完成本轮回测。

## 1. 决策摘要

这三个问题确实暴露了 v3 的设计缺陷：全历史模型过度滞后；把缺少个性化数据错误地当成没有任何可用建议；把模型启用与获得充分在线验证绑定，导致改进无法交付。

建议 v3.1 做三个有限修订，不推倒已有状态机、卡台账和成对模拟器：

| 问题 | v3.1 决定 | 直接效果 |
|---|---|---|
| 跟不上近期变化 | 增加日历时间指数衰减模型 D60，作为新的默认参考模型候选；P0 留作长期对照 | 最近事件贡献更大，长期休眠的影响逐渐减弱 |
| 冷启动没行动 | 新增不依赖学习的规则规划器与余额分配预算 | 第一开机就显示“先留卡/用哪张/何时再看/今天如何控制” |
| 等待 60 天 | 将启用资格、历史回测、在线验证拆开；移除等待 60 个在线预测的硬门槛 | 可在一次开发交付内启用参考版，同时开始记账评分 |

**不承诺 D60 当前就应输出 22.6%，不把 P1 概率更高等同于更准，不要求用户先补数据才能拿到本报告。** 原始数据只影响具体拟合数值和是否通过回测，不影响上述修订方向。

## 2. 事实、解释与本轮未验证事项

用户报告：P0 为 12.7%；近 90 天约 22.6%、180 天约 19.1%、全历史约 13.5%；P1 影子约 15.8%。这些作为现场事实记录，本轮没有重新计算。

这些数字支持“近期事件更密集，需要允许发生率随日历时间变化”的方向。关于平台整体变差的背景判断，不转换成模型系数；算法只消费可观测的事件节奏，避免把一种因果解释写死。

仍需核对“22.6% / 19.1% / 13.5%”分别是什么统计量：

1. 事件次数 / 观察天数：单位其实是次/天。
2. 有至少一次事件的日数 / 总日数：日命中比例。
3. 由发生率换算的 `1-exp(-lambda)`：模型的 24h 概率。

三者不等价，尤其一天发生多次时。如果 22.6% 实际是 0.226 次/天，Poisson 换算的至少一次概率约 20.2%；如果它本身就是日命中比例，则不能再换算一次。12.7% 与 13.5% 的差别也应先核对统计口径和尾段暴露，不能凭差值认定实现错误。

**交付实现不得以“把结果调到 22.6%”为验收条件。** 验收对象是时间加权、正确暴露、无信息泄漏、建议可用性与评分链路。

## 3. 修订一：增加日历时间趋势模型 D60

### 3.1 与 P1 的区别

- P0 回答长期平均发生率是多少。
- P1 回答距离上次平台公告多久，是否改变下一次事件的条件发生率。
- D60 回答最近一段日历时间的平台整体活跃程度是多少。

“距上次事件的年龄”与“过去半年逐渐变频”是两个不同特征。P1 不含日历权重，因此不能指望将 P1 转正就解决趋势问题。

v3.1 先上线单独的 D60，不立即叠加年龄、星期、月份、线性趋势和变点检测。54 条左右的事件不足以支持不断扩张的自由参数。

### 3.2 模型定义

继续预测 v3 的平台目标：未来 `(t,t+24h]` 是否出现 regular 公告事件。用卡和自然重置不进入这个平台训练集；公告到个人账号到账的映射仍然独立。

时间以下均以天计，截点为 t。对覆盖可靠的过去时刻 u：

```text
halfLife = 60 天
k = ln(2) / halfLife
w(t,u) = exp(-k * (t-u))

Cw(t) = sum_i w(t,eventTime[i])
Ew(t) = integral_可靠观察区间 w(t,u) du

lambdaAll(t) = 历史可用事件数 / 历史可用暴露天数
tau = 7 个等效观察日
lambdaD60(t) = (Cw(t) + tau * lambdaAll(t)) / (Ew(t) + tau)

p24(t) = 1 - exp(-lambdaD60(t))
```

60 天半衰期和 7 天收缩强度是此次预先固定的工程默认，**尚未通过本项目数据证明最优**。7 天在这里仅为正则化强度，不能解读成平台按周重置的证据。

收缩用到了与加权统计重叠的历史数据，因此这是带平滑的发生率估计，不将其包装为具有严格独立先验的贝叶斯后验。

可靠连续区间 `[a,b]` 的加权暴露可精确计算：

```text
Ew([a,b]) = [exp(-k*(t-b)) - exp(-k*(t-a))] / k
```

实现中对多个不相交覆盖区间求和。事件分子和暴露分母必须使用同一覆盖范围。

### 3.3 边界约定

1. 采用 v3 已定义的去重 regular 时间序列。
2. 若覆盖起点只是“最早一条已知事件”，条件化于这条起始事件，排除它的计数，从它之后累计暴露；不能凭空添加它之前的无事件天数。
3. 若存在独立证明的更早完整覆盖，可以计入相应暴露和其中事件。
4. 最后一次事件到截点 t 的无事件尾段必须计入。
5. 缺页、未确认补齐的采集空档不能记为无事件暴露。若后续完整历史补齐了空档，可以恢复该段覆盖。
6. 在线仅使用预测时已知记录；历史 firstSeenAt 不存在时，离线回放标注“公告即时可知假设”。
7. 单位统一为天，不把毫秒差直接带入半衰期公式。
8. 历史数据不足以估计平台概率时可以为 null，但冷启动行动规划仍须输出。

### 3.4 行为解释

相对当前截点，同一事件：现在的权重约 1，60 天前为 0.5，120 天前为 0.25，180 天前为 0.125。旧事件不突然在第 91 天被扔掉，显示曲线会比固定 90 天窗口平滑。

持续观察而没有新事件时，分子逐渐衰减、分母继续接收新暴露，估计会下降。近期连发时加权分子更快增加，估计上升。

D60 不作“未来必然越来越频繁”的线性外推。对于当前预测窗口，先冻结当前发生率：

```text
p(t,h) = 1 - exp(-lambdaD60(t) * h)
```

h 单位为天。新的真实观察到达后再更新模型。不能在同一份预测里把假定未来没有事件当成真实负证据，逐小时让发生率自行衰减。

冻结发生率只是短期近似；21–42 天用卡模拟应把长期发生率不确定性作为情景显示，不能将今天的 D60 当作未来 42 天已知不变的规律。

### 3.5 展示与解释因子

默认展示：

> 未来 24 小时平台重置信号：X% · 近期加权参考

展开显示：长期参考、近期时间加权后的差值、半衰期、覆盖天数、加权事件量、模型版本及验证状态。

`Cw` 是折扣后的事件量，不是独立样本数。不要把它写成“已经有 Cw 个独立样本”。若报告有效暴露，可补充 `Eeff = Ew² / integral(w²)`，单位仍为天；它同样不能消除事件聚集或模型错设。

近 90/180 天统计保留为诊断行，但不与 D60 再做任意加分。正式数值始终来自一套明确公式。

### 3.6 与 P1、排期和 watch 的关系

- P0：长期参考及回退模型。
- P1：保留现有影子结果，不因它是原来的“升级候选”就优先转正。
- D60：新的默认参考模型候选。
- 90 天窗口模型：回测对照，帮助判断指数衰减是否真的值得。

v3.1 不再添加第五、第六个候选来追逐当前最佳成绩。年龄×趋势的组合模型推迟；若以后做，事件计数和年龄分段暴露都必须按实际日历时间同步加权，不能简单叠加 P1 与 D60 概率。

scheduled/watch 保持 v3 的目标与窗口约束、incident 去重及情景消费规则。D60 仍不是“排期以外的背景率”，也不是本账号到账概率。

## 4. 修订二：不学习也能明确行动

### 4.1 修改原则

**没有个人需求预测，不等于无法分配现有额度。**

v3.1 将输出拆成：

- `expectedConsumption`：预计用户会用多少；无历史、无预算时仍可为 null。
- `allocationBudget`：系统建议如何分配当前额度；有余额与自然截止即可计算。
- `action`：现在做什么、什么时候再看、什么条件下用卡；有效账号快照下始终有具体值。

冷启动可以使用明确标注的默认策略与假设，但不能伪装为已学习到用户习惯。

### 4.2 默认余额分配公式

设当前周余额 R，下次自然周截止 T，当前时刻 t。默认按剩余时间均匀分配：

```text
remainingHours = (T-t) / 1小时
todayHours = max(0, (min(T,下个北京时间零点)-t) / 1小时)
budgetToday = R * todayHours / remainingHours
budgetUntilReview = R * min(下次查看前小时数, remainingHours) / remainingHours
```

最终预算夹在 `[0,R]`；T<=t 时先要求刷新，禁止除零。只有分配建议、没有工作规律时，使用剩余墙钟时间是明确的默认规则，不声称用户会全天工作。

例如北京中午，剩 40 点，96 小时后自然重置，今天还剩 12 小时：今天剩余时间建议预算为 5 点。它表示“按均匀分配控制在约 5 点”，不是“预测你今天会用 5 点”。

用户可选择“今天多用一点”：将今天的分配权重改为 2，其余时间为 1，再按加权时长归一化，确保总分配仍不超过 R；“今天少用一点”权重为 0.5。权重只改变分配，不创造新额度，不需要用户填写预算。

没有明确执行的卡，不把未来卡的 100 点提前计入确定预算。排期与高平台概率同样不直接扩大这一预算。

### 4.3 默认用量情景：用于比较，不冒充预测

为让既有模拟器在零样本时也能工作，增加 `source='policy_default'` 的虚拟需求：

- 轻用：每 24h 消耗 50/7 个周百分点。
- 均衡：每 24h 消耗 100/7 个周百分点。
- 较忙：每 24h 消耗 200/7 个周百分点。

它们分别表示半个、一个、两个满周额度在七天内用掉的策略情景；数值来自额度尺度，不来自用户历史。初始选“均衡”，用户可一键换档。三个情景不设虚构概率，不平均成用户真实日耗。

初版按各日的剩余时长均匀生成周窗需求；另做集中到一个工作段的压力情景，检查结论是否依赖均匀使用。未指定集中段时可固定使用当前时刻起的首个 4 小时段作为压力构造，并明确不是对用户作息的预测。

短窗没有可识别需求时不虚构周/短窗换算。其当前低余额或耗尽状态通过规则处理，并标记双窗联合模拟尚不完整。

### 4.4 确定性的冷启动行动优先级

下列规则从上往下匹配，命中后返回主动作；到期提醒仍可以并列展示。建议不等于自动执行。

**A. 状态无效或明显过时**

主动作：“先刷新额度”。刷新失败时保留最后状态及时间，不凭旧余额给强用卡建议。这是明确行动，不是“还在学习”。

**B. 周窗或短窗已耗尽**

- 有可确认有效的卡且用户表示要继续工作：建议使用最早截止卡，展示周截止将变成现在加 7 天。
- 尚未表示要继续工作：主动作“先留卡，开始工作前用这张”；不能为了闲置期间回满而无条件消耗卡。
- 无卡：主动作“等到已知受限窗口的自然截止再继续”；若短窗先恢复但周窗仍空，要显示真正阻塞的周截止。
- 卡身份/有效期有冲突：明确建议“先核对这张卡是否还在”，同时给出等待自然恢复的备选。

**C. 到本轮最后安全用卡机会**

用已选默认档运行 v3 的共同视野对比，比较“现在用该卡”与“先不用但以后仍可用卡”，同时列出轻用/较忙情景：

- 选定档用卡能减少不足或增加实际可满足用量，且其他情景没有更严重不足：建议现在用最早截止卡。
- 选定档无益或因推迟自然截止而更差：建议先不用，并清楚说明即便卡过期也不值得为了用卡而用卡。
- 不同情景反转：主动作按用户选定档给出，标注“按均衡档建议”；附一句可执行切换条件，如“如果今天会持续忙，改用较忙档”。不得退回只有“需要学习”。
- 未选择工作量时使用已公开的均衡档，不额外卡住等待输入。

未知短窗机制等会影响结论时保留条件标记，不抹掉明确的主动作与下一次复查时间。

**D. 还没有到最后机会，但默认档在下次查看前可能不够**

使用最早截止卡与等待方案作同样比较：确能减少所选档的不足时建议使用；否则建议减少本段分配或等自然恢复。标注“按默认档”，不声称这是个性化概率保证。

**E. 其他情况**

主动作：“先留卡，今天按约 X 点分配；到 Y 再看。”Y 为下次查看时刻、临期处理时刻、自然截止三者中的最近未来时刻；没有设置查看时段时默认现在起 12 小时，并标为可修改提醒时间，不保证用户一定到场。

**F. 满额且没有迫近的工作需要**

不得只为“零过期”连用多张卡。即便临期也先说明无实际收益；需要提醒，未必需要消耗。

### 4.5 冷启动不再返回空建议

有效快照的标准输出必须包含：

```ts
type ColdStartAdvice = {
  action: 'use_card' | 'hold_card' | 'wait_for_reset' | 'refresh' | 'reconcile_card';
  headline: string;
  allocatedWeeklyPointsToday: number | null;
  nextReviewAt: number | null;
  trigger: string | null;
  basis: 'policy_default' | 'user_plan' | 'learned';
  expectedConsumption: number | null;
  assumptions: string[];
};
```

余额/截止有效但个人历史为空时，预算应有数值；若未量化需求，expectedConsumption 可以仍为空。核心修订是只保留必要的不确定性，不再让整个功能空白。

### 4.6 从默认到学习的过渡

规则规划器长期保留作回退。学习模型是增强，不是启用建议的前置条件。

需求模型有 n 个有效日后，可用经验分布与默认情景作渐进替换：默认质量权重 `alpha=min(n/14,1)`；只有完整、未明显被限流截断的日子增加 n。若要混合分布，明示默认部分是策略先验而非实测；不要将三个人工情景的比例当经验概率。

更简单的首版实现可以不混合：默认档持续工作，达到 v3 的有效样本门槛后提供“改用已学习用量”开关。禁止在第一个异常高用量日突然全面改写策略。

## 5. 修订三：把启用与验证分开

### 5.1 两个状态轴

```text
deployment: reference_active | shadow | fallback
evidence: specified | historical_replay | prospective_tracking | supported
```

模型可以是 `reference_active + historical_replay`，不必先达到 supported 才出现在主界面。反过来，即使过去表现好，数据损坏也应 fallback。

删除“必须积累 60 个在线预测才能启用候选”的硬门槛。60 天可保留为一次回顾节点，不是发布锁。

### 5.2 本次交付就能完成的历史回放

使用现存完整 regular 历史，不需要等待新的两个月：

1. 按北京时间每日 09:00 建立预测截点。
2. 首次覆盖至少 60 天后开始评分；这是已有历史的训练前缀，不是再等待 60 个在线日。
3. 每个截点只用此前记录拟合 P0、P1、D60、R90。
4. 四个模型在同样可评估日期输出未来 24h 概率。
5. R90 使用最近最多 90 个实际覆盖日的事件/暴露率，按同一口径换算概率。
6. 同时报告全评估期、最近 180 天、最近 90 天的 Brier、对数损失和预测/实际比例；每栏写清样本数与正例数。
7. 校准分组先最多 3 组；不足时只显示数值与数量，不画看似平滑的可靠性曲线。
8. 使用相同日期的成对损失差；按 7 天及 14 天区块检查不确定性，避免把聚集事件当作完全独立。

本轮设计已看过最近趋势统计，所以这份历史回放属于辅助验证，不是完全未触碰的独立测试集。真实未来结果仍用于确认持续有效。

firstSeenAt 缺失时，明确标为理想化回放；可附加“延迟 6 小时/24 小时才能看到公告”的压力回放，不能声称这些延迟已经测得。

### 5.3 固定候选，不自动追赢家

本轮固定 D60 参数，不在同一历史上枚举十几个半衰期再宣布最好者已验证。P1 输出 15.8% 并不构成转正证据，R90 更接近用户的近期统计也不构成证据。

若以后调半衰期，必须将调参与评估按时间分开，或采用嵌套时间顺序选择；把参数选择过程一并计入回测。

### 5.4 明确的参考版启用条件

D60 可在以下条件全部满足后成为主参考数值：

1. 公式、覆盖、去重、预测冻结和未来数据隔离测试通过。
2. 同口径历史回放已经产出，最近 90 天存在至少 30 个可评估日；没有足够数据时仍可显示 D60 辅助值，但不宣称完成回放验证。
3. 近期回放没有明显反证：例如 D60 最近 90 天 Brier 比 P0 差超过 0.01，则暂不切为默认，先检查原因。0.01 是预先规定的产品止损阈值，不是统计显著性阈值。
4. 全评估期和对数损失没有被隐藏；若与近期结果方向不一致，在模型说明中写明适用性取舍。
5. 新预测记录与最小标签结算器已接通，能够记录这次发布之后的结果。

无需 Brier 改善达到统计显著才允许参考版启用；也不能把“没有明显反证”写成“已证明更准”。如果回放强烈反对 D60，报告应允许保留 P0 主值并显著展示近期对照，而不是为了满足更高概率而强切。

### 5.5 评分接线尚未合入时怎么办

不能把评分系统继续当一个无限期外部依赖，也不必等完整评分页面。

v3.1 最小交付必须一起带上：

- 发布预测时追加不可变记录。
- 窗口结束后，根据补齐的事件数据结算 0/1/unknown。
- 使用追加 verdict 的方式保存结算，不修改原预测；迟到数据通过新版本纠正标签。
- 一个本地命令或应用内部函数输出按 modelVersion/target 分组的样本数、Brier 和缺失数。

先做日志、结算和数字汇总，完整图表后补。没有日志写入时仍可显示明确标注的“临时参考”，但不能展示“正在在线校准”或“已验证”；实现方应将最小链路与 D60 放在同一发布单元完成。

### 5.6 在线监测与回退

- 同时记录 D60 与 P0；P1/R90 可保留影子，所有模型共享标签。
- 每周回顾一次固定周报，不逐日追逐最小 Brier 自动切模型。
- 计算错误、非有限概率、覆盖判断错误、未来数据泄漏：立即回退并标记原因。
- 性能回退：成熟配对样本达到 28 天后，若最近 28 天 D60 的平均 Brier 比 P0 高超过 0.01，连续两次周回顾出现，触发回退建议；查看正例数量和数据质量后决定，不宣称这是显著性检验。
- supported 状态依据累计的预测、校准和稳定性证据审定；不再规定“第 60 天自动转正”。

28 天和 0.01 都是治理参数，需要版本化；不能混入平台概率公式。

## 7. 实施与验收清单

推荐以三个可独立核验的工作包实现，优先补冷启动，因为它不依赖平台数据回测。

### 工作包 A：立即有建议

1. 拆开日耗预测与额度分配字段。
2. 实现余额/时间分配、默认档和冷启动行动优先级。
3. 界面明确标识“默认分配”，允许一键忙/闲调整。
4. 没有个人历史也能输出主动作、预算和复查时间。

### 工作包 B：趋势与回放

1. 实现 D60 精确加权事件/暴露。
2. 实现四模型同截点回放与固定结果表。
3. 按启用条件选择主参考模型，保留 P0 对照。

### 工作包 C：校准最小闭环

1. 冻结预测日志及版本。
2. 接通窗口结算、迟到纠正、缺覆盖 unknown。
3. 输出按模型统计的数字汇总；接通失败不能谎称正在评分。

### 必须新增或改写的验收行为

1. 两组历史总事件数与总覆盖相同，但一组事件更靠近现在：D60 对后者给更高发生率。
2. 只改变事件距截点 60 天，其权重恰为 0.5；120 天为 0.25。
3. 分子加权但分母不加权的故意变异必须被测试检出。
4. 长时间可靠观察无新事件：D60 逐步下降；缺失区间不能产生同等下降证据。
5. 增加预测截点之后的事件：旧预测完全不变。
6. 个人用卡不改变 D60；banked 事件不进入 regular 模型。
7. 概率换算与次数/天分开；0.226 次/天不能直接显示 22.6% 发生概率。
8. R=40、剩余 96h、今天余 12h：均匀分配为 5 点；不是预测日耗。
9. 无个人日志、无预算、有正常快照：不能只有“正在学习”；必须有预算、主动作和下一检查点。
10. 余额耗尽且无卡：明确等待哪个窗口恢复；短窗恢复不能解决空周窗。
11. 默认较忙档与均衡档用卡结论不同：展示选定档建议和翻转条件，不伪造两档概率。
12. 临期用卡会取消即将自然补给且整体更差：不能因为卡临期就推荐使用。
13. 已满且闲置、多张临期卡：不连续空打卡。
14. 候选模型可处于 reference_active + historical_replay；不得被旧的 60 天判断挡住。
15. 发布后一条预测能够在窗口成熟后被结算并计入对应版本 Brier。
16. 迟到数据修正标签但不修改原始预测概率；覆盖不完整的窗口不是负例。

上述是后续实现验收要求，本次报告没有执行这些测试。

## 8. 如需算出当前具体数值，最小数据清单

无需新的个人用量历史即可继续实现。要计算 D60 当前值和回放结论，只需要：

- 去重 regular 原始数组：id、announced_at、类型、来源；保留修订关系。
- 同一统计截点、可确认覆盖起止及缺页/缺口说明。
- 90/180/全历史百分比的分子、分母及换算公式。
- 如果已有 firstSeenAt，则一并提供；没有也可做标注清楚的理想化回放。

本轮不需要为了完成提案额外向用户索取数据。拿到上述内容后，才可填入“当前 D60=X%、近期 Brier 改善=Y”的实际结果。本文不预填这些值。

## 9. 交付结论

v3.1 应当让产品从第一天就有行动建议，并允许近期事件改变参考预测；更成熟的个人需求与在线校准负责改进这些建议，而不是决定用户是否配得到建议。

本报告提出了明确公式、冷启动决策顺序、模型启用条件和测试要求。半衰期与默认工作量属于公开的产品假设，用户反馈的数据属于现场证据，模型是否更准仍由可复现回放及后续预测记录回答。
