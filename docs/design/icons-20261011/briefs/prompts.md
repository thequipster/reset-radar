# 03｜reset-radar 生图提示词

> 阶段 3 · 2026-10-11 · 用户最新裁决：只约定 UI/UX，不固定配色、风格、字体或材质。此前方案的视觉取值不约束本轮生图。
> 版本 v1 · RR26 / agent/RR26。下面六个代码块各自可单独复制。没有指定画图模型，未调用生图工具；这是一组待人工生成参考图的提示词，不声称已验证图片生成效果。

## 使用顺序

先用第 1 组生成展开态，可让 AI 提供不同视觉探索；选中一张后，把它作为图片参考，再分别用第 2–6 组补齐其它视图。每次生成一张，建议比例可按模型支持调整。

不需要把 01/02 的旧色值、设计技能的示例色板或原界面截图一并作为视觉指令。图稿只要满足下面的内容与交互关系，视觉语言由画图 AI 决定。选中参考图后，才确定实际字体、间距、圆角、色板和主题默认值。

画图模型常会错拼中文与数字；此轮首先检查区域、层级与交互可读性，准确文案和真实数字由阶段 4 前端接线保证。示例数值是演示内容，不代表当前账户，不要求 AI 推导配速、收益或风险公式。

## 01 · 展开态全貌（先生成这一张）

```text
你是一位桌面工具 UI/UX 设计师。为 reset-radar 设计一张 Windows 桌面悬浮工具的展开态界面参考图。它服务于 Codex CLI 用户：查看额度强制重置风险，规划今日用量和重置卡使用时机。

场景与视角：正面平视，完整展示一个窄而纵向的工具面板，面板是画面主角。以真实可操作的界面设计稿表达内容，可留少量桌面背景解释悬浮关系。

区域划分：顶部是 reset-radar / CODEX 名称及主题、收起、退出入口。其下留独立的公告/采集状态区域：有公告时写“公告：计划于 MM/DD HH:mm 北京时间重置，尚未确认发生”，附来源与获取时间。再下方先显示周额度剩余29%和短窗剩余64%，突出“今日建议追加8.7个周额度百分点”，并显示建议执行后的剩余量。均匀配速、风险前拉、软上限、最终建议作为四项可解释信息，软上限表达约束。中部是“未来24h强制重置模型风险25.4%”与“48h碰撞估计58.0%”，以及四条示例解释因子，每条有名称、带正负号的百分点贡献和可展开说明。下部是重置卡×3、用卡建议“等待最佳用卡日”、今天与最佳日的期望收益（期望额外消耗的周额度百分点）、最佳日期、自然重置时间，以及按候选日期比较期望收益的小图。底部是额度观测时间、数据来源、刷新额度、复制摘要和校准入口，零计分样本时写“数据积累中”。

交互与信息层级：用户先读懂剩余额度与今日行动，再查看理由和规划。详细内容可以纵向滚动，收起和退出始终可达；长说明可以展开。周额度、短窗、模型风险、期望收益各有准确标签。所有数字为演示数据；用卡建议不代表自动执行，公告不代表已发生。

视觉自由：请自行决定配色、深浅主题、字体、图标、材质、形状和整体视觉风格，用你认为合适的视觉语言呈现这些UIUX。保留清楚的阅读层级、可识别控件和易读中文。

画幅：建议3:4竖幅。输出一张界面参考图。
```

## 02 · 悬浮条特写

```text
你是一位桌面工具 UI/UX 设计师。为 reset-radar 设计一张收起状态的悬浮条特写。它是给 Codex CLI 用户常驻桌面查看周额度和强制重置模型风险的小工具。

场景与视角：正面平视，画面主体是一条完整横向工具条，周围留少量空间说明它悬浮在桌面上。

区域划分：左侧是独立拖动把手与 CODEX 标识；中间以“29% 周余”为主读数，旁边为“25.4% 风险”的次级读数；右侧是重置卡“×3”和明确的展开入口。工具条另有小型采集状态标记，完整状态说明可以在预览层查看。

交互与信息层级：一眼看出周额度剩余、模型风险和卡数，各组不能互相混淆。数字全部示例，风险完整语义为未来24h强制重置模型估计。拖动区域与展开按钮分开，条形本身紧凑，不为收起状态留下大片空面板。未知卡数显示“卡 —”，已知零张显示“卡 ×0”。请让展开入口容易发现、容易点击。

视觉自由：若提供了已选中的展开态参考图，请延续它的视觉语言；没有参考图时，自由选择配色、风格、字体、材质和形状，不预设任何主题。优先清楚表达上述UIUX关系。

画幅：建议6:1横幅。模型不支持时可用4:1画布，但工具条保持窄长横向比例，增加周围背景而非把工具条拉高。输出一张完整悬浮条参考图。
```

## 03 · 悬停 / 键盘聚焦迷你预览

```text
你是一位桌面工具 UI/UX 设计师。为 reset-radar 设计悬浮条的迷你预览态，让 Codex CLI 用户不用打开完整面板也能看到今日行动。

场景与视角：正面平视，完整显示悬浮条和紧邻它的预览区域，像真实桌面工具被悬停或键盘聚焦时的状态。

区域划分：上方保留悬浮条：左为拖动把手与CODEX，中为29%周余和25.4%模型风险，右为卡×3和展开入口。下方预览第一行突出“今日建议追加8.7个周额度百分点”，第二行是“等待最佳用卡日”的简短用卡建议。底部左侧标注额度观测时刻“MM/DD HH:mm 北京时间”，右侧有“查看完整规划”入口。有公告时在预览中优先显示公告计划时刻，用卡详细建议移入完整面板。

交互与信息层级：条和预览明显属于同一个工具；鼠标可以移入预览而不让它立即消失。预览内容也能通过键盘获得，点击完整规划后进入持久展开态。区分暂时预览与完整展开，不需要把所有因子和收益图塞进这里。所有数字为演示数据，公告注明计划、尚未确认发生。

视觉自由：有已选中的主界面参考图时保持视觉一致；否则配色、主题、字体、形状、材质与风格自行发挥。通过合理排版表达条与预览的层级关系。

画幅：建议3:2横幅。输出一张完整预览态参考图。
```

## 04 · 关键组件与解释方式

```text
你是一位桌面工具 UI/UX 设计师。为 reset-radar 生成一张关键组件设计板，用来说明额度、风险、今日建议和用卡规划怎样被清楚呈现。

场景与视角：正面平视，以组件设计稿的方式展示几个可嵌入同一桌面面板的部件，每个组件有足够阅读空间。

区域划分：左上是周额度与短窗额度组件，分别显示示例29%和64%，明确标签；右上是今日追加建议组件，主数值示例8.7个周额度百分点，下方分解均匀配速、风险前拉、软上限和最终建议，软上限是约束而非额外相加的份额。左下是风险解释组件，模型风险示例25.4%，解释因子有正负号、百分点、名称和说明入口，用布局体现贡献方向；四条只是示例，不暗示因子数量固定。右下是用卡规划组件，含“等待最佳用卡日”、卡×3、今天与最佳日期的期望收益对照（期望额外消耗的周额度百分点）、自然重置时刻，以及候选日期收益小图。组件旁或下方可放一个公告示例：计划时刻、来源、获取时间、尚未确认发生。

交互与信息层级：单位紧随数字，百分比余额与追加用量/收益百分点有区别；展开说明入口可识别。期望收益是模型估计，日期图是候选用卡日期比较，不是实际消耗历史。不同概念既有标签也有视觉区分，不能只靠颜色辨认。

视觉自由：由你决定色彩、字体、图表形式、材质、边界与风格。若附有选中的展开态图，所有组件沿用该图的视觉语言。保持读数、说明和控件的清楚层级。

画幅：建议4:3横幅。输出一张组件设计板。
```

## 05 · 全状态对照

```text
你是一位桌面工具 UI/UX 设计师。为 reset-radar 生成一张同一工具的全状态对照设计板，说明用户在数据还没到、失效或缺失时会看到什么。

场景与视角：正面平视，将六个同尺寸的小面板排成两行三列，保持同一套布局与视觉语言。

区域划分：左上为首次加载，保留工具壳与结构占位，写“读取中”，无假余额或假进度；中上为空数据，额度显示“—”，写“暂无额度数据”，提供刷新额度入口；右上为首次采集失败，显示简洁可读的失败信息与重试入口，数字仍为占位。左下为数据过期stale，保留上次观测的29%余额，明确写“数据过期 / 上次观测 MM/DD HH:mm”，旧建议注明依据上次观测，刷新入口可达；中下为已知卡数零张，写“卡×0 / 无可用重置卡”，其他额度和风险继续显示；右下为卡数未知，写“卡数未知 / 卡 —”，不显示确定的无卡决策或确定用卡收益。每个小面板都保留收起/退出入口位置。

交互与信息层级：加载、空数据、失败和旧数据过期在文字和结构上能区分，不能只换一个颜色。未知值不变成0，失败不抹掉可信的旧值。失败或stale可以与公告独立共存；只在真正刷新中表达“刷新中”，不要把未知状态画成实时成功。所有演示数字与时间不是当前账户数据。

视觉自由：自行决定各状态的图标、插图、颜色、字体、材质与风格。若提供主界面参考图，延续它的视觉语言。请兼顾状态可识别与工具整体一致，不把错误态变成难以阅读的满屏技术异常。

画幅：建议3:2横幅。输出一张六状态对照图。
```

## 06 · 同一界面的深浅主题对照

```text
你是一位桌面工具 UI/UX 设计师。为 reset-radar 的同一个展开态设计深色与浅色两种阅读主题，不预设任何具体色系。

场景与视角：正面平视，两张完整窄面板并排展示，左侧为深色阅读主题，右侧为浅色阅读主题。两者使用完全相同的数据、控件、区块顺序与内容密度。

区域划分：每张面板顶部是CODEX / reset-radar、主题切换、收起与退出；上部是公告/数据状态位置、周余29%、短窗64%和今日建议追加8.7个周额度百分点及四项解释；中部是未来24h模型风险25.4%、48h碰撞估计58.0%和带正负贡献的因子；下部是卡×3、用卡决策、期望收益对照（期望额外消耗的周额度百分点）、候选日期收益图、自然重置时刻；底部是数据观测时间、刷新额度、复制摘要、校准入口。所有数值标为演示。

交互与信息层级：切换主题不改变单位、数据含义、位置或可用操作。两边都易读，余额、风险、公告、异常既有文字标签也有视觉区分。公告只表达公开来源的计划，尚未确认发生；期望收益仍是估计。

视觉自由：深色和浅色的具体色彩、风格、字体、材质与形状由你自由决定；若附有已选中的参考图，以它为基础设计另一主题，保留同一产品的家族感。此图用来探索两种阅读环境，不指定最终默认主题。

画幅：建议4:3横幅。输出一张双主题对照图。
```

## 回图检查与交接

- 先选信息层级最清楚的展开态，再检查其它图是否保留同一套读数、控件语义与产品视觉语言。
- 查看悬浮条五组内容是否完整；今日建议是否标“追加”与周额度百分点；软上限是否被误画成加项。
- 检查卡×0与卡数未知是否不同，stale是否保留旧值并标时刻，公告是否仍为计划状态；不用图片里的错字作为代码数据来源。
- 六组提示词做过文档结构/关键语义校验；没有实际生成图片或跨模型效果评测，不给虚构成功率。实际图稿布局错误时按对应区域补充提示后重生成。
- 推荐保存命名：`01-expanded.png`、`02-compact.png`、`03-peek.png`、`04-components.png`、`05-states.png`、`06-themes.png`。只是交接命名，不要求画图AI在图上写文件名。
- 本分支参考图目录为 `docs/design/ref/`。至少选中的展开态与悬浮条应到位；其它视图有参考图可减少阶段4的解释偏差。
- 阶段4沿用用户新增授权：除UI重构，还逐卡执行公告、日志、数据新鲜度、CI与校准任务。当前先停在阶段3，等用户参考图后再实施，不自动生成图，也不提前改业务代码。

事实出处：用户阶段3裁决优先于最初要求的具体hex与风格词；02-spec的UIUX与状态定义；src/ui/adapters.ts的DashboardViewModel/buildDashboard及src/lib输出类型。公告和校准展示为阶段4关联卡待接入能力，不声称当前已有完整数据链。
